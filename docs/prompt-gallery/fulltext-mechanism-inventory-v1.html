OSTARA W09 SUPPLEMENTARY FULL-TEXT MECHANISM INVENTORY v1
You are coding already retrieved scholarly full texts about collective action
in commodity supply chains. Return one JSON object, no markdown.
Evaluate EVERY approved ontology mechanism in approved_ontology (not only
abstract-assigned mechanisms). Use EXACT mechanism_id values from the table.
Use the entire supplied fulltext, not solely its abstract. Do not infer
absence of a mechanism merely because the abstract omits it.
For each approved mechanism classify status:
- implemented_case: direct source support that at least one described
  initiative/case actually uses this mechanism
- mentioned_only: discussed as context/theory or comparative mechanism,
  but not shown to operate in an extracted case
- proposed_only: prospective, recommended or hypothetical application only
- not_identified: no relevant description found in this full text
- unclear: relevant text is ambiguous
Use at most one status per ontology ID. For all positive/unclear statuses
provide a verbatim short source_quote and its exact [PAGE n], [SECTION n] or
[TEXT BLOCK n] source_anchor. Never fabricate quotes or print page numbers
for XML/JSON. Provide case_ids only for implemented_case. Match case_ids
from eligible_case_ids ONLY. Other IDs in existing_w09_cases are not eligible\nand must not be used for implemented mechanisms or novel case proposals.\nDo not invent new IDs. A publication can mention
mechanisms outside its cases; keep those separate.
For every original W07 novel proposal in w07_abstract_novelty explicitly
assess full-text support: confirmed_novel, refined_novel,
covered_by_existing, rejected or uncertain. Identify exactly which
approved ontology code subsumes a proposal, if applicable. Give a quote and
anchor for positive decisions. Do not silently turn a novel mechanism
proposal into an approved code.
Independently propose truly NEW mechanisms in new_novelty only when they
are not covered by ANY approved ontology mechanism and are demonstrated
in a case. Explain the novelty in relation to closest existing codes.
Each proposal requires a full-text quote and source anchor and existing
case ID. If a proposal is also one of the abstract suggestions, link to it
in abstract_novelty_validation rather than double-count it.
This is extraction, not final adjudication. Human review will determine
actual case eligibility, supported coding and ontology changes.
Do not extract effectiveness or impact conclusions.
